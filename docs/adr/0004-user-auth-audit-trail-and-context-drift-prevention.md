# ADR 0004: 多使用者自動建檔認證、全量審計日誌與多輪對話防失焦架構

## 狀態 (Status)
**已接受 (Accepted)** (2026-09-03)

## 背景 (Context)
IBM FlashSystem / SVC 專家系統目前已具備 PIN 碼防護與外網 Web 入口。為因應團隊近 80 位工程師日常諮詢與維運稽核需求，系統需要：
1. **零負擔使用者帳號體系**：避免管理者手動建立與維護 80 個帳號。
2. **全量審計與計費追蹤**：完整保存同仁問答歷程、官方來源引用、Token 與費用消耗。
3. **多輪對話防失焦 (Anti-Context Drift)**：在同一個對話中進行連續追問時，避免因歷史 2 萬字 RAG 手冊疊加導致注意力稀釋或跨主題混亂。

## 決策 (Decision)

1. **Auto-Provisioning 認證模型**：
   - 採用 SQLite + JWT Token 架構。
   - 同仁首次登入時輸入工號/姓名與密碼，系統自動註冊帳號並開闢獨立會話空間；後續以 JWT Token 驗證並自動記住於瀏覽器。
2. **Audit Trail Engine 全量審計引擎**：
   - 建立 `storage_audit.db`，包含 `users`, `sessions`, `chat_audit_logs` 三層關聯表。
   - 記錄提問原文、完整解答 Markdown、檢索引用之官方手冊清單 (JSON)、Token 消耗量、估算費用與耗時。
3. **Smart Context Isolation 智慧防失焦機制**：
   - **單輪 RAG 隔離鐵律**：每一題檢索出的 25 筆原廠手冊只在該輪生效，下一題的歷史 Prompt 僅攜帶問答純文字對話，絕不疊加舊題的幾萬字手冊。
   - **話題切換重置**：當同仁開啟新主題時，自動清空舊主題 RAG 上下文；追問時則透過輕量指代消解還原完整主語。
4. **ChatGPT 風格雙欄 UI**：
   - 左側支援歷史對話側邊欄（依日期分組 + 一鍵開新對話），右上角顯示個人資訊。

## 後果 (Consequences)
- **正面影響**：
  - 管理者零帳號維護負擔。
  - 對話歷程可完整追溯，方便知識沈澱與費用審計。
  - 多輪對話保持極致精準，杜絕跨主題注意力混亂。
- **負面影響**：
  - 需新增 SQLite 審計資料庫與 JWT 認證中介層。
