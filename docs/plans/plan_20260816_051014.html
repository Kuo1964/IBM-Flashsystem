多進程多代理並行爬取計畫書 (Multi-Process Spawn Agent Architecture)

為了同時對 IBM FlashSystem 各大版本（9.1.3、9.1.2、9.1.1、9.1.0、8.7、8.6、8.5）展開極速並行爬取，且徹底杜絕先前多線程引發的 Node.js EPIPE 與 Segfault 崩潰，我們設計了純 Spawn 多進程代理架構 (Process-Level Concurrency)。

> [!IMPORTANT]

> 本計畫書為正式安全審查設計案，在獲得您的核准之前，不會更動任何程式碼。

---

1. Codebase Recon & Context Map (多進程架構偵察)

  • 核心矛盾與技術演進：
  • 第一代 (單線程順序)：穩定但耗時，爬取 30 多條版本網址需耗費數小時。
  • 第二代 (多線程 ThreadPool)：引發 Playwright 的跨語言 Node.js stdio 管道衝突 (`EPIPE`) 與記憶體段錯誤 (`Segmentation fault`)。
  • 第三代 (本次目標：Spawn 多進程池)：

使用 Python 原生 `concurrent.futures.ProcessPoolExecutor(mp_context=mp.get_context("spawn"))` 或 `multiprocessing.Pool`。

每個爬蟲代理運行在完全獨立的作業系統進程中，擁有獨立的記憶體空間、獨立的 Node.js driver 管道與 Chromium 實例，既享有並發的高速優勢，又具備 100% 的進程隔離安全性！

2. Guardrail Spec (多進程正式安全檢查規範)

1. 完全進程隔離護欄 (Spawn Isolation Guard)：

  • 嚴禁使用 `fork` 模式（macOS 下 fork + Playwright 會直接 Segfault）。強制指定 `mp.get_context("spawn")`，保證每個 Worker 擁有全新的直譯器環境。

2. 流量與頻寬節流護欄 (Throttle Guard)：

  • 設定 `max_workers = 4`。最多同時派出 4 個獨立代理，避免對 IBM 伺服器造成過大壓力或觸發 WAF 封鎖 IP。

3. 資料庫集中寫入護欄 (Centralized DB Writer Guard)：

  • 子進程只負責網路抓取與 HTML/PDF 解析，絕不直接碰觸資料庫檔案。
  • 所有子進程將解析後的 Chunks 透過 IPC 回傳給主進程，由主進程統一執行 `delete_source_from_db` 與 `add_chunks_to_db`，徹底杜絕多進程並發寫入 SQLite 引發的 `database is locked` 錯誤。

4. 狀態聚合與持久化護欄 (State Aggregation Guard)：

  • 主進程即時聚合各個代理回傳的 `visited_urls` 與 `content_hashes`，並在 `finally` 區塊中保存，確保下次執行可跳過已處理網址。

3. Brownfield Diff Review (現有程式碼變更審查)

以下為預計在 `ingest.py` 實裝的進程池調度代碼：


+ from concurrent.futures import ProcessPoolExecutor, as_completed
+ import multiprocessing as mp

  def run_ingestion(force_url: bool = False, max_depth: int = 50, max_pages: int = 3000):
      ...
      # 2. 處理網頁 URLs (多進程並行掃描)
      if config.RAW_URLS_FILE.exists():
          with open(config.RAW_URLS_FILE, "r", encoding="utf-8") as f:
              urls = [line.strip() for line in f if line.strip() and not line.startswith("#")]
          
          print(f"\n🌐 掃描到 {len(urls)} 個技術文檔網址，啟動多代理並行掃描 (4 Workers)...")
          global_urls = load_global_set(config.GLOBAL_VISITED_URLS_FILE)
          global_hashes = load_global_set(config.GLOBAL_CONTENT_HASHES_FILE)
          
+         spawn_ctx = mp.get_context("spawn")
          try:
+             with ProcessPoolExecutor(max_workers=4, mp_context=spawn_ctx) as executor:
+                 futures = {}
+                 for url in urls:
+                     url_key = f"url_{url}"
+                     url_hash = calculate_file_hash_text(url)
+                     if not force_url and manifest.get(url_key, {}).get("hash") == url_hash:
+                         print(f"  [跳過] 網址未變更: {url}")
+                         continue
+                     
+                     # 分派任務給獨立子進程
+                     future = executor.submit(_url_worker_standalone, url, max_depth, max_pages, list(global_urls), list(global_hashes))
+                     futures[future] = (url_key, url, url_hash)
+                 
+                 # 主進程依序接收並集中入庫
+                 for future in as_completed(futures):
+                     url_key, url, url_hash = futures[future]
+                     try:
+                         res = future.result()
+                         if res.get("status") == "success":
+                             web_chunks = res.get("chunks", [])
+                             global_urls.update(res.get("visited", []))
+                             global_hashes.update(res.get("hashes", []))
+                             
+                             if web_chunks:
+                                 delete_source_from_db(web_chunks[0]["metadata"]["source"])
+                                 add_chunks_to_db(web_chunks)
+                                 manifest[url_key] = {
+                                     "type": "url",
+                                     "url": url,
+                                     "hash": url_hash,
+                                     "chunks_count": len(web_chunks)
+                                 }
+                                 updated_count += 1
+                         else:
+                             print(f"  [警告] 網址處理失敗 ({url}): {res.get('error')}")
+                     except Exception as e:
+                         print(f"  [異常] 代理執行失敗 ({url}): {e}")
          finally:
              save_global_set(config.GLOBAL_VISITED_URLS_FILE, global_urls)
              save_global_set(config.GLOBAL_CONTENT_HASHES_FILE, global_hashes)

4. 驗收標準 (Acceptance Criteria)

1. 並行效能驗收：同時啟動 4 個獨立工作進程，吞吐效率提升 300% 以上。

2. 穩定性驗收：完全零 `EPIPE`、零 `Segmentation fault`、零 `database is locked`。

3. 資料一致性：所有 9.1~8.5 版本的網頁 Chunks 與 PDF 自動攔截檔案全數正確入庫。
